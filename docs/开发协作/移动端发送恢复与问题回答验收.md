# 移动端发送恢复与问题回答验收

## 已完成任务的发送按钮恢复（2026-10-30，待统一发布）

已复现的边界：`currentPendingDelivery()` 还保留已送达但未出现在当前历史页的消息，或旧 POST 一直不返回时，任务摘要虽然已完成，按钮仍被全局 `sending` 禁用。任务切换恢复会克隆 pending 对象，不能只修改旧请求闭包里的对象来解除界面状态。

- 已保存消息的送达状态与输入框分离：输入文字／图片时可继续保存并提交，未确认消息仍按同一任务原顺序进入持久 Outbox；终态和其他任务的请求不再占用当前任务的发送按钮。
- 同任务、adapter 与 clientId 的原生用户消息、持久 Outbox 接收记录或 delivered 回执，都可结束浏览器等待，不必等原 POST 返回。回执解除的是网络请求，不是伪造 Agent 结束。
- 附件恢复、模型确认与 POST 整体最多等待 30 秒；超时保留内容，用同 clientId 核对接收。已过期的附件／模型异步准备不得随后偷偷发送；迟到响应也不能修改下一条消息的锁和状态。收到回执后取消无用的 HTTP 等待，不取消桌面任务。
- 停止接口返回没有运行时主动回读状态；不靠删除历史、附件、缓存或另建任务解锁。

回归入口：`test/daemon/mobile-composer-recovery.test.ts`。隔离网页验证使用真实网页脚本及回环 HTTP 夹具：故意不返回 POST，轮询返回接收及完成，连续提交两条文字及一条图片请求，下一次输入的发送按钮仍可用。不是生产 Codex、ClawBot 或微信 WebView 的真机验收。

## 行为约定

- 网页请求使用同一 `clientId` 重试；临时网络失败采用退避重试，不弹重复的失败提示，也不设置六次后永久停止的上限。
- 同一任务按发送顺序交给后台；永久无效的输入保留为可修复记录，但不永久阻塞后续输入。
- 后台只对明确的连接尚未建立、终端尚未就绪、限流等情形持续退避。无法确认是否已被 Agent 接收的请求先核对真实记录，不能为了重试而重复执行。
- 图片原件存入浏览器 IndexedDB，任务缓存只保留附件索引，不把大图塞入 localStorage。刷新恢复时校验图片数量与原件，缺失时不允许以纯文本替代图片消息。后台已接收后可清理本地附件副本。
- 缓存保留终端、真实/临时任务 ID、附件索引和重试策略；禁止将 `undefined` 或 `null` 当作任务 ID 发送。
- 问题回答与权限审批是两种操作：问题卡片展示单选、多选及自定义输入，答案通过独立接口发回原终端原任务，并校验当前问题标识。刷新卡片不清掉尚未提交的选项。
- **兼容候选暂缓普通本地文件自动推送**：原候选新增的本地 Markdown 成品链接自动识别、`attachmentsOnly` 转发和相关测试假设均不纳入。既有显式附件发送能力不回退；Codex 生成图片继续使用上下文恢复基线的持久队列，全部文本和图片确认后才记录完成。
- 有真实时间戳的连续消息段按发生时间排序；没有时间证据的消息保留原始相对位置，不捏造时间。记忆保存工具显示对应的过程状态。
- 新任务准备阶段不查询不存在的任务模型/权限接口；所选模型不支持图片时保留原请求，明确提示换模型后重试，不自动换模型或丢图。

## 已知边界

1. 旧版已清除且从未上传的图片原件无法从剩余文字还原，需要用户重新附图。
2. 浏览器存储不可用时必须明确提示，不能声称已耐久保存。尚未被后台接收的请求仍依赖浏览器继续运行或重新打开；后台已接收的请求由持久发件箱接管。
3. 未收到终端确认不等于执行失败；禁止仅凭一次超时自动创建新任务、改终端或重发不确定的操作。
4. 已识别的记忆工具过程可显示；终端没有提供的内部状态不能伪造。
5. 本次为部署前兼容提交，不自行部署，不包含真实微信附件投递或手机微信内置浏览器端到端验收。
6. 普通文件自动推送仍保留在原候选 `524d451` 供后续完善。恢复该功能前，必须为各终端增加普通文件的持久检查点、失败重试、去重与目标锁定；不能在图片/文件尚未发完时报告整个通知已发送。

## 消息与队列去重回归（2026-10-29，待统一发布）

- 图片消息：原生记录包含图片占位、图片编号或闭合标签时，仍与网页临时消息合并。前后端共用正文归一化；刷新恢复时保留附件数量。
- 排队消息：网页 `clientId` 随发送进入 Codex 原生队列，原生状态先于 RPC 回执出现时按身份接管。旧队列无 `clientId` 时，只在时间、正文和附件数量均符合条件时一对一合并，不以相同文字批量删除消息。
- 后台恢复：迟到图片回执使用原任务、相同 turn 和正文找回已保存的原图；不能仅用相似文字补图后判为成功。无法确认时保留原消息，不自动重发。
- 迟到响应：已确认送达或取消的记录不能被尚未结束的发送请求恢复为排队或失败。同一网页请求重试命中已有原生队列项时复用该项。
- 合成验收覆盖：图片真实记录先到、POST 后到；原生队列先到、发送回执后到；连续快照、重启恢复、一对一回执、不同请求身份的同文消息、取消后迟到响应。浏览器实测使用编译后网页脚本和 loopback 夹具，不向真实 Agent 或 ClawBot 发送测试消息。
- 边界：不批量删除真实用户历史；无法可靠匹配的旧记录仍保留。桌面实际保留扩展队列身份及手机微信 WebView 体验由统一部署后用户验收，本开发任务不安装、不部署。

新增定向测试：`mobile-message-text.test.ts`、`mobile-message-recovery.test.ts`、`mobile-message-image-store.test.ts`、`mobile-message-continuity.test.ts`，并扩展原有队列、Outbox、Codex adapter 和 HTTP/网页回归。
