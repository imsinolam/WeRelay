# WeRelay 多 Agent 任务职责

> 更新日期：2026-08-18
> 目标：让 WeRelay 的长期任务按稳定能力域分工，避免同一个问题被多个 Agent 重复实现、互相覆盖或分别发布。

WeRelay 可以由多个 Agent 并行开发，但每项需求必须有唯一的工程 owner。具体的 worktree、提交交接、未提交改动分类和发版规则以[多 Agent 协作规范](多Agent协作规范.md)为准。

## 核心原则

1. 电脑端真实 Agent 是任务、上下文、工具和权限的唯一 owner。
2. 微信 ClawBot、局域网网页和公网网页只接入并继续原任务，不创建隐藏的替代会话。
3. 一个长期任务对应一个稳定能力域，不为每个 Bug 新建长期任务。
4. 每项功能只有一个开发 owner；跨域修改由主 owner 协调，不能让多个 Agent 同时覆盖同一文件。
5. 开发任务只负责实现、测试和本地提交；正式发布由用户明确指定的发布 Agent 统一完成。
6. 问题按真实根因归属，而不是按用户最终看到问题的界面归属。

## 能力域与职责

### 产品与体验验收

负责：

- 明确用户场景、优先级和验收标准。
- 评审微信、网页和电脑端三端体验。
- 复现问题并判断真实链路归属。
- 发布后使用真实手机、真实任务完成最终验收。
- 守住“继续同一条真实任务，不制造第二个 owner”的产品原则。

不负责：

- 不长期承担跨模块实现。
- 不直接发布正式版本或部署生产环境。
- 不把多个能力域的开发长期堆积在同一个任务中。

### 核心运行时与 ClawBot

负责：

- 微信消息收发、长轮询和连接恢复。
- ClawBot 任务列表、搜索、选择、数字直发和新建任务。
- 入站消息、完成通知、审批通知和任务链接去重。
- 微信图片暂存、批量合并、确认和取消。
- daemon 生命周期、状态持久化、空闲启动和重启恢复。
- Relay Client 与公网服务器之间的设备连接。

主要代码范围：

```text
src/wechat/*
src/daemon/werelay-daemon.ts
src/daemon/daemon-state.ts
src/daemon/*delivery*
src/daemon/*deferred*
```

### 移动网页与公网 Relay

负责：

- 局域网和公网移动网页。
- 任务看板、项目折叠、搜索、分页和项目内新建任务。
- 消息正文、缓存、异步更新、乐观消息和排队消息。
- 运行进展、完成状态、图片上传和历史图片恢复。
- 审批卡片显示、定位和操作。
- 登录、会话认证、HTTPS、短链接和 Relay 网页请求。
- 移动端布局、触摸、长按、文字选择和浏览器兼容性。

主要代码范围：

```text
src/daemon/codex-mobile-web.ts
src/daemon/codex-mobile-server.ts
src/daemon/codex-mobile-auth.ts
src/daemon/mobile-message-image-store.ts
src/relay/*
```

### Agent 适配与桌面同步

负责：

- 保证远程入口操作电脑端原任务，而不是创建替代会话。
- Codex Desktop 的任务、turn、request、状态、writer 和审批同步。
- WorkBuddy Desktop 的真实任务和桌面 RPC 接入。
- Claude Code、TClaude、Grok、CodeBuddy、reasonix、DeepSeek Harness 和 OpenCode 适配。
- Agent 任务枚举、恢复、发送、停止、审批、待输入和模型能力。
- Companion、IPC、Socket 和桌面 owner 管理。
- Provider 依赖检测、能力声明和安全的预定义安装入口。

主要代码范围：

```text
src/bridge/bridge-adapters.*.ts
src/bridge/codex-desktop-ipc.ts
src/bridge/workbuddy-desktop-rpc.ts
src/companion/*
src/runtime/*
```

### 架构、质量与跨平台

负责：

- 模块职责、依赖方向、循环依赖和长期缓存审计。
- 安全边界、隐私扫描和公网风险审计。
- Windows、macOS、Linux 兼容性。
- CI、测试覆盖、测试隔离和失败归因。
- worktree、旧分支和已发布临时产物的清理建议。
- 对跨模块高风险修改做独立评审。

不负责：

- 不在审计过程中顺带发布正式版本。
- 不用大范围重写替代可验证的小修复。

### 官网、文档与公开演示

负责：

- README、产品说明、安装说明、安全说明和官网文案。
- 演示数据、截图、视频和公开素材。
- 统一表达 WeRelay 的产品关系和使用方式。
- 防止公开素材泄露真实项目、任务、账号和基础设施信息。

不负责：

- 不描述尚未真实实现或验收的能力。
- 不为生成演示素材污染用户真实任务数据。

### 发布与部署

负责：

- 接收明确的候选提交和验收清单。
- 在独立 release worktree 中整合、解决冲突并准备版本。
- 更新版本号和面向用户的中英文版本说明。
- 运行完整质量检查、打包检查和安装验收。
- 通过专用发布服务器的隔离目录提交并推送 GitHub。
- 生成并验收本地 tarball；在用户明确授权时发布 GitHub 版本、部署公网 Relay 并完成线上验活。

不负责：

- 不在发布过程中临时开发业务功能。
- 不把主工作区所有未提交内容直接当作发布输入。
- 不从开发 Mac 直接向 GitHub 推送。

## 常见问题归属

### 审批

| 现象 | 归属能力域 |
| --- | --- |
| Desktop 有审批，但 Adapter 没识别 | Agent 适配与桌面同步 |
| 已识别审批，但 ClawBot 没推送 | 核心运行时与 ClawBot |
| API 有审批，但网页没有卡片 | 移动网页与公网 Relay |
| 网页有卡片，但点击不能定位或处理 | 移动网页与公网 Relay |
| 审批修复需要改变多层协议 | 架构、质量与跨平台先审查 |

### 消息重复或错序

| 现象 | 归属能力域 |
| --- | --- |
| 微信同一条入站消息被消费两次 | 核心运行时与 ClawBot |
| Adapter 向同一任务提交两次 | Agent 适配与桌面同步 |
| API 只有一条，网页渲染成两条 | 移动网页与公网 Relay |
| 发布后本机与公网版本不一致 | 发布与部署 |

### 性能

| 现象 | 归属能力域 |
| --- | --- |
| 微信长轮询卡死或重连慢 | 核心运行时与 ClawBot |
| Agent 历史读取或任务恢复慢 | Agent 适配与桌面同步 |
| 网页首屏、正文和分页慢 | 移动网页与公网 Relay |
| 超长任务导致模块资源异常 | 架构、质量与跨平台 |

## 标准交接

开发 Agent 完成后向发布 Agent 提供：

```text
提交号
用户可见变化
主要修改文件
实际通过的测试
依赖提交
未解决风险
发布后验收清单
```

没有提交号、测试仍失败或职责归属不清的修改，不进入正式发布候选。
