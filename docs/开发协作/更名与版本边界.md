# DeskRelay 更名为 WeRelay：名称与版本边界

> 本文是开发与发布 Agent 的事实真源。开始修改仓库前，先用本文确认当前项目身份，不能根据本机目录名、旧分支名或历史版本记录判断产品名称和版本线。

## 当前项目身份

DeskRelay 已完成对外更名，当前项目统一使用 **WeRelay**。

| 范围 | 当前唯一名称 |
| --- | --- |
| 产品名 | `WeRelay` |
| GitHub 仓库 | `imsinolam/WeRelay` |
| 本地安装包标识 | `werelay` |
| CLI 命令 | `werelay`、`werelay-*` |
| 运行数据目录 | `~/.werelay` |
| 环境变量前缀 | `WERELAY_*` |
| 正式版前的版本线 | `0.x.x` |

新功能、新文档、新配置、新服务文件和面向用户的提示都必须使用当前名称。不得重新引入 `deskrelay` 命令、`DESKRELAY_*` 活动配置或第二套公开包名。

## 为什么仓库附近仍会看到 DeskRelay

出现旧名称不等于项目仍叫 DeskRelay，也不表示应把代码改回旧命名。旧名称只允许出现在以下有明确理由的范围：

1. **本机历史目录名**：已经存在的源码目录或 worktree 父目录可能仍叫 `DeskRelay`。目录名只是本机路径，不是产品身份；不要为了“统一名称”擅自移动或删除它，否则可能破坏其他 Agent 的 worktree、后台服务和本地脚本。
2. **一次性数据迁移**：WeRelay 会从 `~/.deskrelay`、`DESKRELAY_*` 或更早状态复制缺失数据。这里的旧名称是兼容输入，不是当前活动配置。
3. **迁移测试与历史说明**：测试夹具、迁移表格和历史版本记录需要保留旧名称，才能证明升级路径仍然有效。
4. **旧分支与旧提交**：历史分支、提交标题和 worktree 名称不会因产品更名自动改变。它们只能作为候选改动来源，不能作为当前发布基线。

除以上范围外，新增的 `DeskRelay`、`deskrelay-*`、`~/.deskrelay` 或 `DESKRELAY_*` 一般应视为命名回退，并在提交前纠正。

## Agent 开始工作时如何判断目标

1. 先读取当前 worktree 根目录的 `AGENTS.md`、`package.json` 和本文。
2. 以 `package.json` 中的 `name`、版本号和 GitHub 仓库配置判断当前产品，不以父目录名判断。
3. 检查 `git worktree list`、当前分支和提交基线。旧 DeskRelay worktree 中的完成提交可以审查后按 SHA 合入，但不能直接把旧工作树当成最新版发布。
4. 用户仍口头说“DeskRelay”时，默认理解为当前 WeRelay 项目；只有用户明确讨论迁移、旧命令、旧数据或历史版本时，才按旧产品语境处理。
5. 修改旧名称前先判断它是否属于迁移兼容或历史事实。禁止无差别全仓替换。

## 版本规则

- 用户尚未确认正式版，因此新版本继续使用 `0.x.x`。
- `2.0.0`、`2.1.x` 等记录是早期预览编号，只用于历史追溯，不是当前版本线。
- 不得因为看到旧 `release/2.x` 分支或历史文档，就把下一版本升级为 `2.x`。
- 只有唯一发布 Agent 可以确定并修改正式版本号；普通开发 Agent 只提交功能或文档改动。
- 当前版本以最新发布基线的 `package.json` 和[版本记录索引](../发布/版本记录/版本索引.md)为准。

## 提交前检查

涉及名称、安装、配置、服务或版本时，至少确认：

- 用户可见内容只使用 WeRelay；
- 新命令使用 `werelay-*`；
- 新状态写入 `~/.werelay`；
- 新环境变量使用 `WERELAY_*`；
- 旧名称只保留在迁移、测试或历史上下文中；
- 版本仍沿用当前 `0.x.x` 版本线；
- 没有移动或清理其他 Agent 的旧名称 worktree。
