# 提交与部署记录模板

这份模板用于记录每一次 Agent 提交、体验部署和正式发布。目的不是增加形式工作，而是确保出现“未提交、安装了错误版本、无法找到来源”时，可以按时间和任务准确反查。

## 记录

```text
时间：YYYY-MM-DD HH:mm:ss +时区
操作：提交 / 体验部署 / 正式部署 / GitHub 发布 / 回滚
Agent：<Agent 名称或平台>
AI 模型：<实际模型；无法确认时写 unknown>
任务名：<Codex task 标题>
任务 ID：<Codex task/thread ID>
项目：WeRelay
工作树：<绝对路径>
分支：<branch>
基线提交：<完整 SHA>
提交：<完整 SHA；没有提交则写“无，不得作为部署输入”>
版本：<x.y.z 或 preview 版本>
产物：<tarball 绝对路径>
产物 SHA-256：<完整 SHA>
安装/部署路径：<绝对路径或服务名>
验证：<命令、HTTP 地址、结果和时间>
未验证风险：<没有则写“无”>
备注：<冲突、来源、审批或其他说明>
```

## 填写规则

1. `时间` 使用实际操作时间并带时区，不能只写“今天”或“刚才”。
2. `Agent`、`AI 模型`、`任务名`和`任务 ID`必须来自当前任务的真实上下文；无法确认时写 `unknown`，禁止猜测或借用其他任务的信息。
3. 提交记录使用完整 commit SHA；部署记录必须同时记录源码 SHA 和产物 SHA-256。
4. 没有提交 SHA、产物 SHA 或清晰来源的内容只能保留在开发现场，不能安装到本机运行，也不能部署公网。
5. 如果一个版本曾经生成过 tarball，后续内容必须递增版本号，不能覆盖旧包。
6. 验证失败必须原样记录，不能把“进程启动”写成“功能通过”。

## 最小示例

```text
时间：2026-09-12 18:30:00 +0800
操作：体验部署
Agent：发布与部署
AI 模型：unknown
任务名：WR｜发布与部署
任务 ID：<完整 task ID>
项目：WeRelay
工作树：/srv/projects/werelay/worktrees/release-candidate
分支：codex/release-candidate
基线提交：<完整 SHA>
提交：<完整 SHA>
版本：0.3.13-preview.20260912.4
产物：/srv/projects/werelay/artifacts/candidate/werelay-0.3.13-preview.20260912.4.tgz
产物 SHA-256：<完整 SHA>
安装/部署路径：/Users/example/.nvm/versions/node/v24.18.0/lib/node_modules/werelay
验证：health HTTP 200；完整测试通过；网页和设备在线链路待验证
未验证风险：微信发送仍处于退避保护，未宣称通过
备注：同一 tarball SHA 安装，未推 GitHub
```
