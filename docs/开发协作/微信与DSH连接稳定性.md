# 微信与 DSH 连接稳定性规范

> 本文记录 WeRelay 在 2026 年 9 月发现并修复的一类连接假故障与实际断连问题。后续 Agent 修改核心运行时、任务列表或 DSH 适配器时，必须按本文验证，不能只看到“事件连接已恢复”就判定稳定。

## 现象与判断边界

微信 ClawBot、移动网页和 DSH 事件同时出现超时，通常包含多个独立链路：

1. 微信长轮询：电脑是否能持续收到微信消息。
2. WeRelay 主进程：事件循环是否仍能及时处理定时器、HTTP、WebSocket 和文件回调。
3. DSH Desktop：本机回环 HTTP 与事件 WebSocket 是否可达。
4. 公网 Relay：本机主动 HTTPS/WSS 连接及服务器保活是否可达。
5. 任务目录：各 Agent 的历史目录或接口读取是否及时。

“事件连接已恢复”只表示一次新的连接成功，不能证明后续持续稳定。验收必须同时记录：微信收发、DSH 事件、任务目录、localhost health、公网 health 和主进程延迟。

## 已确认的根因

### 1. 任务目录探测曾在主事件循环中同步执行

`ps`、历史文件扫描、JSON/SQLite 读取在任务列表请求中叠加时，会延迟 WeRelay 主进程。主进程延迟会同时影响 DSH 心跳、微信发送、Relay 保活和移动网页，因此不能只给 DSH 增加重连次数。

要求：

- 终端进程探测使用有超时的异步子进程调用；失败必须表示“未知”，不能伪装成空列表。
- 任务目录读取使用后台 Worker；单个终端超时不得终止其他终端的目录请求。
- Worker 必须有单终端隔离、请求上限、超时和空闲回收，不能让任务列表增长造成常驻资源泄漏。
- 任务列表读取不能同步等待 DSH 事件流恢复。

### 2. DSH 历史快照与长期事件流不能共用可互相关闭的物理连接

DSH 2.0.9 的 `remote.mux` 支持多个逻辑流。历史 `session/follow` 读取可能因大快照、取消、超时或帧积压关闭载体；如果审批和 `$events` 也复用同一个载体，历史读取失败会连带丢失事件通知。

要求：

- DSH 长期 `$events` 使用独立的 `DeepSeekHarnessRemoteMux`。
- 历史快照、任务读取和临时操作使用另一个 mux。
- 任一历史读取失败，只能影响该次历史读取；不得关闭或清空事件 mux。
- 每个物理连接仍需有连接超时、帧积压上限、取消清理和重连退避。
- 事件恢复通知应以稳定连接窗口为准，不能把短暂握手成功误报为长期恢复。

### 3. 主机资源竞争必须作为独立证据记录

高 CPU 的其他任务、系统唤醒、磁盘 I/O 或代理/DNS 超时都可能造成相同外观。不得未经证据杀掉其他项目进程，也不得把锁屏直接等同于睡眠。

WeRelay 启动后每秒记录一次轻量事件循环延迟；超过阈值时限频写入 `daemon_event_loop_lag`。该诊断失败不得影响主服务。诊断日志只记录耗时和类别，不写凭据、消息正文或附件内容。

## 后续 Agent 禁止的做法

- 不得恢复单个 daemon 主线程中的同步 `ps`、大文件扫描或全量历史 JSON 解析。
- 不得把所有终端目录读取重新合并为一个无隔离 Worker。
- 不得让任务列表刷新、历史回放或附件处理等待 DSH `$events` 连接。
- 不得在 DSH 断线时自动重启桌面应用或抢前台；先记录可验证的连接原因。
- 不得通过增加固定重试次数、延长超时或隐藏提示来替代根因修复。
- 不得用“任务列表读到了”证明事件、审批、微信和公网链路均正常。

## 必须保留的回归测试

至少覆盖：

- 一个终端目录读取超时，不影响另一个终端的请求；超时 Worker 会被替换并回收。
- DSH 历史 `session/follow` 连接失败，不关闭独立 `$events`，审批和事件仍可到达。
- DSH 主进程事件循环出现延迟时，客户端心跳仍能维持；诊断记录延迟但不会使 daemon 退出。
- 事件恢复必须在稳定窗口后才通知；短暂连接后立即断开不能提示“已恢复”。
- 任务列表请求期间，微信新指令仍能先被接收和路由，历史补发在后台有界执行。
- 本机 health、公网 health、任务列表、DSH 事件、微信测试消息分别验收，不能合并成单一“服务在线”断言。

## 发布验收顺序

1. 在隔离目录运行隐私扫描、lint、源代码类型检查、相关测试、全量测试、build 和 pack dry-run。
2. 安装候选包后先检查版本、进程命令、daemon endpoint 和本机 health。
3. 连续至少 10 分钟采样本机 health、公网 health、DSH 回环接口和 Relay `deviceOnline`；记录延迟、错误与事件循环 lag。
4. 再做一次真实微信任务列表、`/dsh`、数字直发和审批测试；测试消息必须使用专用验收任务，不能污染用户任务。
5. 只有微信收发、DSH 事件、历史读取、任务列表和公网链路都通过，才可报告“稳定性验收通过”。否则必须保留失败证据并明确是哪个链路失败。
6. 发布 Agent 需要把候选 SHA、安装版本、采样摘要、失败证据和回滚版本写入部署审计记录。开发 Agent 不得自行替换运行版本或推送 GitHub。
