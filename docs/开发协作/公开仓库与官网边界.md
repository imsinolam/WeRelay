# 公开仓库与官网边界

WeRelay 开源程序与品牌官网分别维护。官网源码、营销文案和演示素材在独立私有仓库维护，不是安装程序、自建 Relay 或运行手机任务台的前提。

## 公开仓库保留什么

- Agent 适配、微信连接、手机任务台、应用层 Relay，以及运行必需的内嵌品牌资源。
- 测试、CI、安全检查、许可和贡献说明。
- 脱敏的配置与自建部署示例。
- 用户文档、架构说明、正式版本说明，以及避免旧基线开发和并发覆盖的协作规则。
- README 实际引用、已经审查过的图片。删除已有图片前还要核对官网等外部引用。

## 私有官网仓库保留什么

- 官网 HTML、样式、脚本、字体及其第三方许可。
- 营销文案、演示数据、设计源文件、官网专用品牌生成工具。
- 经过单独审查、允许对访客展示的演示图片与视频。

私有不等于可以存放秘密。私有 Git 仓库同样不得提交密钥、真实环境文件、用户聊天截图或运行日志。历史设计草稿先放本机忽略的归档区，完成审查后才决定是否进入私有 Git 历史。

## 修改与交付

1. 官网需求在私有官网仓库工作，不在此仓库恢复 `website/`、`docs/官网素材/` 或官网专用生成脚本。这些目录既被忽略，也受当前快照隐私检查保护；不得强制暂存绕过。
2. 手机任务台不是品牌官网。不能为了精简官网而删除 `src/daemon/` 下的网页、认证或品牌资源。
3. 跨仓库需求分别验证、分别提交。官网部署与程序部署分开记录，不自动触发彼此发布。
4. 公开快照和安装包均不得携带官网私有资料。禁止从含有私有草稿的工作目录直接打包发布。
5. 这次分离不改写已公开历史。历史中的非敏感演示资料仍可追溯；若发现真实凭据，先撤销或轮换凭据，再单独处理历史和缓存。

具体本机目录、服务器地址、私有仓库访问方式和迁移清单只记在私有交付记录，不写入公开项目。
