# 内部子任务：不占列表，审批仍可到达

## 用户可见规则

- Guardian 自动评审、内部子 Agent 等有真实子任务来源的会话，不出现在 ClawBot 的全部任务、终端筛选、搜索及分页结果中，也不占运行中数量。
- 网页任务列表、任务台和最近完成区遵循同一规则；隐藏内部任务不删除原会话，也不改变父任务内容。
- 内部任务完成不单独推送正文、图片、附件、完成汇总或积压提醒，用户回复“推送”也不补发这类结果。
- 内部任务真正需要用户决定的审批仍按现有审批队列推送，保留编号及任务链接；自动评审的 JSON 完成结果不是待审批事件。
- 普通主任务不受影响。即使用户把主任务命名为“Guardian review”，也不能只因名字被隐藏。

## 根因及实现契约

0.3.20 的积压提醒修复已经上线，但没有同时纳入先前独立开发的子任务来源过滤及其元数据依赖。因此，“有积压去重”不等于“会过滤内部评审”。今后整合必须检验实际安装产物，不能只看旧开发文档或提交标题。

共用 `task-origin` 策略识别真实父任务身份、`source = subagent`、结构化或 JSON 来源，以及 `source.subagent.thread_spawn` 和 `source.subagent.other`。不得用任务标题、回复正文或是否含 JSON 代替来源判断；也不得丢弃非 `thread_spawn` 形态。

### 列表与编号

1. Codex 只读 SQLite 目录与原生列表默认先过滤再截取条数，防止内部任务挤满页数。旧数据库缺少来源字段时，读取 rollout 的首条元数据，每个文件最多读取 64 KiB，不读整份对话。
2. 全终端索引再次过滤并保留已知来源；较新的轻量记录缺字段，不可抹掉已知子任务身份。同名或同 sessionId 的其他 adapter 不受影响。
3. 已发送的快照在后台确认某条为内部任务时，移除可见条目但退役原编号，不能把后面的任务顶上该编号；新增任务也不能复用退役编号。只有用户明确刷新全部列表才重新排序编号。
4. 持久化最近完成的兜底记录必须再次按真实来源分类，不能把过滤掉的任务重新补进列表；读取失败时跳过该可选兜底，不能把正常列表一起变成错误。
5. 浏览器旧缓存不含来源信息，升级时仅使旧任务索引失效一次；会话缓存和未发送草稿保留。新索引恢复后仍支持缓存先展示、后台静默更新。

### 完成与审批分流

- 实时完成、桌面历史扫描、持久化队列重放、屏幕汇总、积压询问与确认补发，都在读取正文、媒体和分配列表身份前遵守来源策略。
- 历史队列中的子任务完成记录用 `suppressed` 原因移除正文及媒体路径，只保留有限身份去重凭证；不能谎称“微信已送达”，也不能伪装为过期。
- 定向 Codex 来源读取放在现有有界目录 Worker 中，优先按数据库 ID 查找，必要时只读已有 rollout；不选择/恢复任务，不启动桌面应用，不创建新 owner。失败时保留待发送项，交由既有恢复机制处理。
- 审批不使用完成静默策略。后台 Codex 观察器以显式 `includeInternal` 获取子任务并继续跟随其审批，但该原始目录不能填充用户列表缓存。审批及待输入问题的文本格式化可以只读来源以避免把内部任务重新插回列表；来源读取失败也不能阻断这些真实用户操作。
- 普通主任务完成、现有屏幕通知策略及[积压提醒一次规则](积压通知规则.md)保持不变。

当前明确接入的是 Codex 来源元数据。其他 adapter 提供相同真实父任务/来源字段时可复用策略；未提供来源的终端保持原行为，不靠名字猜测。

## 必须保留的回归

- Guardian `other`、`thread_spawn`、旧字符串来源、只有父任务字段、仅 rollout 提供来源；同名正常主任务及跨 adapter 同 ID 不误伤。
- 全部/单终端列表、搜索、分页、运行数量、稳定编号、数字直发；过滤先于可见条数上限。
- 网页有/无 slot 的列表、任务台、最近完成兜底，以及升级时旧列表缓存失效但草稿不丢。
- 实时/被动完成、重启补发、屏幕汇总、积压提醒及手动补发均过滤子任务；静默凭证重启去重且不保留答案/媒体路径。
- 子任务审批继续被观察和投递，不因隐藏列表而丢审批，也不为发审批或待输入问题重新插入列表。
- 原有积压只随成功任务列表提醒一次、过期清理和普通主任务通知仍通过。

本轮为开发修复，基于 0.3.20，不修改版本号；安装、真实微信验收与正式发布须由唯一整合/发布负责人按既有流程执行。代码提交不代表正在运行的副本已经更新。
