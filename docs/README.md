# WeRelay 文档导航

这里按“先使用、再理解、后开发和发布”的顺序整理文档。除 `README.md` 这个 GitHub 约定入口外，文档目录和文件统一使用清晰的中文名称；代码目录、协议名和产品名保留原名。

## 第一次使用

1. [项目介绍](使用指南/项目介绍.md)：先理解 WeRelay 解决什么问题，以及哪些 Agent 能继续电脑上的真实任务。
2. [从 GitHub 安装与更新 WeRelay](使用指南/GitHub源码安装与更新.md)：从公开源码构建本地安装包，并理解为什么不需要 npm 公共包。
3. [Agent 安装与配置](使用指南/Agent安装与配置.md)：安装所需 Agent、完成登录并启动 WeRelay。
4. [5 分钟启用局域网移动网页](使用指南/局域网移动网页快速开始.md)：没有公网服务器时完成首次密码设置和手机端到端验收。
5. [运行配置](使用指南/运行配置.md)：查看环境变量、数据目录、后台启动方式和 DeskRelay → WeRelay 迁移说明。
6. [公网 Relay Agent 配置与验收](使用指南/公网Relay配置与验收.md)：可直接交给用户 Agent 执行的服务器部署、验收和回滚 Runbook。
7. [问题排查](使用指南/问题排查.md)：处理微信、终端、网页、Relay 和安装问题。

- [任务台模型与推理设置](使用指南/任务台模型与推理设置.md)：选择原任务实际支持的模型和推理强度。

## 开发与多 Agent 协作

公网设备连接的 WSS 协议、长轮询回退、实施顺序及验收边界见[公网 WebSocket 设备通道](架构设计/公网WebSocket设备通道.md)。

所有参与开发、体验部署或正式发布的 Agent 开始工作前，至少阅读前四项：

1. [DeskRelay 更名为 WeRelay：名称与版本边界](开发协作/更名与版本边界.md)：确认当前产品名、允许保留旧名称的范围，以及正式版前使用 `0.x.x` 的版本规则。
2. [多 Agent 协作规范](开发协作/多Agent协作规范.md)：工作树、提交交接、未提交改动处理和统一版本、部署与公开责任的强制规则。
3. [统一版本、部署与 GitHub 发布](发布/体验部署与正式发布.md)：开发提交、体验候选、观察期和 GitHub 正式发布之间的边界。
4. [任务职责与分工](开发协作/任务职责与分工.md)：各长期任务的能力边界和问题归属。
5. [开发与测试](开发协作/开发与测试.md)：源码运行、测试、构建和打包方法。

- [内部子任务与通知规则](开发协作/内部子任务与通知规则.md)：隐藏内部评审和子任务完成，保留真实审批，防止旧缓存与历史完成记录绕过过滤。

## 官网与公开资源

官网源码、营销文案和演示素材在独立私有仓库维护，不是 WeRelay 安装、运行或自建 Relay 的依赖。
本仓库保留移动任务台、Relay、测试、自建部署示例，以及 README 实际使用的已审查图片。

- [公开仓库与官网边界](开发协作/公开仓库与官网边界.md)：哪些内容可以提交，哪些内容应留在私有官网项目。
- `images/`：README 和公开说明使用的已审查资源；保留既有地址，避免外部引用失效。

## 文档维护约定

- 面向普通用户的内容优先使用中文和可直接执行的步骤。
- 一个主题只保留一个事实真源；其他文档通过链接引用，不复制整段规则。
- 改名或移动文档时，必须同时修复 README、AGENTS、CONTRIBUTING、SECURITY、源码提示、测试和版本说明中的路径。
- 中文版本记录是面向用户的主说明，英文版使用 `-英文.md` 后缀。
- 文档不得记录真实服务器地址、本地任务 ID、访问令牌、运行日志或未审查截图。
