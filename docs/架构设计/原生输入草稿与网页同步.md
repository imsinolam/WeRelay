# 原生输入草稿与网页同步

## 用户可见规则

网页打开同一个任务时，可以读取电脑端输入框中**尚未发送的文字草稿**。保留原文字、空格和空行，不拿上一条用户消息或 AI 回复冒充草稿。

- 网页没有自己的文字或图片时，才自动填入电脑端草稿。
- 网页可修改后直接发送，仍进入原 Agent 的同一任务、同一 owner。
- 电脑端已经发送或清空时，网页中尚未修改的导入草稿随下一次成功读取清除。
- 网页已经改过的内容不会被异步读取覆盖。两端同时修改或电脑先发送时，保留网页内容并提示冲突；只有用户确认后，才作为一条新消息发送。
- 切换任务和终端时，草稿按 `adapter + sessionId` 隔离；迟到的读取结果不能填到其他任务。
- 网页发出后不再回填同一版本。发送失败或结果未确认时，内容留在现有持久 Outbox 中，可查看状态、复制及重试；不恢复一份旧输入造成重复。

## 接入矩阵与真实边界

| 终端 | 本次数据来源 | 能力与限制 |
| --- | --- | --- |
| Codex Desktop | 本地持久化的 `composer-prompt-drafts-v2`，旧版本没有该字段时才读 v1 | 精确读取 `local:<sessionId>` 的纯文字及已识别的文字文档节点。不打开任务、不启动桌面应用、不写回 Codex 全局状态文件。 |
| Pi 原 TUI / 提供编辑器 API 的原 owner | 已认证 owner 扩展中的 `ui.getEditorText()` | 仅 `hasUI` 且提供读写编辑器 API 时支持；原 owner 内同步校验版本、清除旧编辑框，再提交网页修改后的文字。 |
| Pi Desktop 原生会话 | 同一 owner 扩展 | 是否支持取决于实际运行实例是否向扩展暴露编辑器 API；能列目录、能发送消息**不等于**能读其界面草稿。没有编辑器 API 时不导入。 |
| DSH、WorkBuddy 等其他终端 | 当前已接入协议没有完整、安全的编辑器草稿能力 | 不推断、不读取剪贴板、不切换窗口抓取内容，也不另建 owner。后续须由 adapter 提供同一草稿契约后再开放。 |

Pi 已打开的旧 owner 需在适当时机加载更新后的扩展（TUI 可用 `/reload`）；WeRelay 不强制重启应用或打断正在运行的任务。

当前同步范围是**完整纯文字**，不是跨应用的富文本/附件迁移。Codex 草稿带有未知节点、附件或未表示的非空上下文时，整份拒绝自动导入，不能静默丢失一部分后声称已完整同步。网页仍可正常输入自己的内容。读取不截断；现有消息发送的 20,000 字符限制不变，超限明确拒绝而不是截断。

## 契约与链路

`BridgeAdapter.getSessionComposerDraft(sessionId)` 返回：

```ts
{
  supported: boolean;
  draft: { text: string; revision: string } | null;
  unavailableReason?: string;
}
```

`supported: true, draft: null` 才表示确定没有草稿；断线、读取失败和能力缺失不等同于清空。Legacy runtime 保留可选能力并绑定原 adapter 的 `this`。

1. 网页调用已认证的 `GET /api/tasks/:id/composer-draft?adapter=...`。
2. daemon 只用已有 slot，不为读取而启动、选中、恢复任务或创建写者。Pi 对未附着但可发现的唯一原 owner 使用认证短连接，读取后等 `release` 回执再返回。
3. 接口使用 `no-store`，不纳入 Relay 预热或 warm cache，也不允许仅凭预热令牌读取。公网仍通过原应用层中继转发。
4. 网页应用结果前再次比对任务、终端、请求代次、输入修改代次和输入原值；未修改的缓存导入稿重新进入时先校验，不先闪现可能已发送的旧稿。
5. 网页发送携带 `composerDraftRevision` 和稳定 `clientId`，版本持久化到已有 Outbox；不同页面对同一任务同一草稿版本不能创建两条提交。
6. adapter 在实际投递前校验版本。草稿已变更时停止自动重试，保留用户内容；普通网络中断仍沿用原有幂等恢复。

## 版本、清理与隐私

- Pi 的版本属于原编辑器代次，输入事件、会话切换和观察到文字变化均使旧版本失效；版本化发送在原 owner 同步比较并清空，重复 `clientId` 回执不会把已结束任务重新标为运行中。同步提交失败时仅在编辑器仍空的情况下恢复，不能覆盖用户新输入。
- Codex 原生持久化记录没有独立编辑代次。WeRelay 对每任务文字指纹维护私有、不透明的版本代次，观察到清空后即使重新输入同文也算新稿；其他任务变化不影响该任务。不使用全局文件 mtime 作为草稿版本。
- Codex 版本表最多 512 项；Outbox 的已提交草稿回执最多 2048 项，浏览器每会话最多保留 8 个已消费版本，并受现有会话缓存数量限制。额外回执只含摘要/随机标识，不保存文字；文件使用私有原子写入和 `0600` 权限。
- 原文字只沿现有已认证消息/草稿链路传输，不另写调试日志，不收集进公开验收材料。浏览器沿用现有本机草稿缓存，退出登录时清除。

### 不能伪装解决的限制

本轮范围已确认：两端同时发送的竞态暂不处理，不作为此次开发交付的阻塞项；保留现有版本校验和重复提交保护。此约定不代表可以省略正常发送与已发送不回填的验收。

Codex 当前接入的 owner IPC **没有原子 compare-and-clear 编辑器方法**。本次在实际发送/入队前再次读原记录，但不能原子清除电脑框，也不能完全排除电脑与网页在最后瞬间同时发送。网页成功提交后通过持久回执避免重复导入；电脑端可能仍留下原文字，用户在电脑继续发送前应检查。禁止为绕过限制直接改写 Codex 全局 JSON、注入应用或开启第二 writer。

若 Codex 在两次读取之间完成“清空后重输完全相同文字”，原记录本身无法区分代际，会保守视为旧版本。长期超过有界回执容量同样不承诺永久去重。后续应优先接入原 owner 的原子草稿接口，而不是以时间猜测或历史消息匹配代替。

## 防回归验证

- `native-composer-draft.test.ts`：真实存储形状、现代空 store 优先、全文/空行、精确任务、未知上下文拒绝、代次跨重启与私有权限。
- `pi-composer-draft.test.ts`：UTF-8 跨 socket 分片、读取释放、编辑后发同一 owner、版本冲突、重复提交、失败恢复及重复回执不伪造运行态。
- `mobile-composer-draft.test.ts`：认证、禁止预热、`no-store`、发送版本贯通、多标签去重、回执超出正文保留期后仍有效。
- `mobile-composer-draft-web.test.ts`：完整回填、已发送清除、网页修改保护、迟到响应/跨任务隔离、未改旧缓存校验、已消费版本不回流、冲突不自动重试。
- `relay-composer-draft.test.ts`：真实本地 Relay/client 链路中两次读取返回不同最新结果，不缓存原草稿。
- `test/fixtures/pi/verify-native-composer-draft.mjs`：使用已安装 Pi SDK 创建临时假模型会话，禁用网络和工具，验证原 owner 读、改、发、清除、去重与冲突。参数是已安装 SDK 的文件 URL，不包含凭据。

真实浏览器验收使用隔离假任务与临时服务：多行回填、网页改后只发送一次、切换回来/刷新不回流、电脑清空后网页同步清除、两端冲突时保留网页修改。发布整合后还须在获准的真实任务做一次目标 Agent 验收；不能用模拟成功冒称所有桌面终端都已可用。
