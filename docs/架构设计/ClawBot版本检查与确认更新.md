# ClawBot 版本检查与确认更新

本次修复针对“有预发布 Release 却不提醒、回复更新也不能安装”。这不是放宽发布权限：开发 Agent 仍只交付提交，维护者安装/部署/发布由各自授权控制。普通已安装用户可以在微信明确确认更新自己的全局副本。

## 来源与版本契约

- `src/utils/github-release.ts` 是 CLI 与 ClawBot 共用的已发布版本目录。
- 先读本仓库 `/releases?per_page=100`，排除 draft；API 被限流或不可用时读同仓库 `releases.atom`，不回退 `/releases/latest`、tags 或 main。前者只返回正式版，后两者不能证明经过发布。
- 在有界响应内按完整 SemVer 选择最高版本，不用发布时间或 tag 字符串排序。正式版高于相同主版本的预发布，但下一补丁的预发布高于旧正式版；build metadata 不改变优先级。
- URL 从仓库常量与严格验证过的真实 tag 构造，不信任 API 的 `html_url`；下载保留原 tag 是否有 `v` 前缀，不自己猜。
- 目录只检查 API 最近 100 个 Release；Atom 只提供 GitHub 当前 feed 的条目。它不是无限历史枚举，未来若出现大量重新发布旧 tag，需再评估分页。

## 检查、提醒与安装分离

`ClawbotUpdateNotifier` 持久保存 policyVersion、checkedAt、latest、notifiedVersion、notifiedAt。策略更新会刷新旧 stable-only 缓存一次；成功查询每 24 小时一次，失败间隔 1 小时重试。成功提醒最多每 24 小时一次；微信发送失败不记录送达，新入站可以立即重试。当前安装版本按需读取，不保留启动时的旧版本常量。

`ClawbotUpdateController` 只认完整指令，不把“更新一下网页”解释为软件更新。只有绑定用户的消息能进入它；“检查更新”只读，“更新”或 `/update` 才安装。同步占用进程内 job，再启动后台 Promise，不能 await 在微信入站循环上。升级执行器还有用户级跨 workspace 锁，避免多 daemon 覆盖同一个全局安装。失败发送反馈时不开始安装，不假设微信上下文能靠持续发消息续期。

## 安装安全边界

执行器不接受任意下载地址，只从已确认的 tag 构造本仓库归档 URL；拒绝版本不一致、同版本和降级。临时目录私有，下载有大小和超时限制。解压前检查路径、单根目录与条目类型，拒绝越界、符号链接及特殊文件。运行 npm 前校验 package name、完整目标版本和依赖锁；依赖用 npm ci，产物用 npm pack，安装前核实 tarball 身份和安全文件名。命令执行复用已有 PATH/Windows cmd 包装，不使用 shell 拼接，也不从 npm Registry 下载 WeRelay。

只接受当前 module 对应的真实全局包，不自动查找别的全局副本，不覆盖源码 checkout 或软链接。安装固定 prefix 与当前包一致。替换前备份包、旧/新命令入口及回退清单；安装失败、版本不匹配、命令入口缺失或 `--help` 启动失败会恢复包和 shims，回退失败显式报错并保留备份。成功备份也保留，不自动清理用户回退点。

停止服务时取消尚未替换的工作并等待 job；一旦进入全局安装，必须完成安装校验或回退，不在中间放弃。下载/依赖/构建不阻塞入站，但 npm 覆盖运行目录仍有风险，不能承诺绝不影响当前或新启动的入口。硬断电/强制 kill 可能留下备份与锁；下次只能清理确认原 PID 已死亡的锁，不能仅按时间抢锁。

安装完成不自动重启、不改变 provider/模型/代理/权限设置。单独收到“重启”后，仅在已知 macOS launchd 标签、实时 PID 与当前 daemon 一致且具备 keepalive 属性时依赖保活退出；手动进程或未知 supervisor 不退出，避免微信永久离线。不自动更新公网 Relay。

## 防回归检查

重点覆盖：正式/预发布、完整尾号排序、stable 与 rc、draft/tag/main 排除、API 限流 feed 回退、响应体超时、旧缓存迁移、每日限制、失败发送/新入站恢复、重启去重；确认与仅查询分离、后台非阻塞、跨 workspace 锁、源码身份/不安全归档/打包路径拒绝、替换失败和版本校验失败回退。实际跨版本安装、强制断电和 Windows/macOS/Linux 本机安装仍应由部署候选验收，单元测试不代替生产验活。
