# 局域网与公网访问

WeRelay 在 daemon 中内置移动网页服务。用户不配置服务器时，网页自动作为局域网入口运行；配置公网 Relay 后，同一网页还可以通过 HTTPS 从外部网络访问。

两种模式操作的都是电脑端真实 Agent 任务。公网 Relay 不运行 Agent，也不会在桌面任务不可用时创建独立 CLI、ACP 或替代会话。

## 先选择使用方式

| 使用方式 | 适合场景 | 手机网页 | 需要服务器 |
| --- | --- | --- | --- |
| 局域网网页 | 手机和电脑通常处于同一 Wi-Fi | 直接访问电脑 | 否 |
| 微信 ClawBot | 希望在外网查看、发消息、审批和接收完成通知 | 不依赖网页 | 否 |
| 公网 Relay | 希望在外部网络使用完整移动网页 | HTTPS 访问 Relay | 是 |

推荐阅读顺序：

1. 新用户先完成 [5 分钟启用局域网移动网页](../使用指南/局域网移动网页快速开始.md)；
2. 确认局域网、密码和真实任务都正常；
3. 确实需要外网网页时，再把 [公网 Relay Agent Runbook](../使用指南/公网Relay配置与验收.md) 交给用户的 Agent 执行。

## 无服务器模式

启动 daemon：

```bash
cd /path/to/your/project
werelay --idle-start --no-open
```

如果明确希望启动时立即连接某个终端，也可以使用 `werelay --adapter codex` 或 `werelay --adapter deepseek`。后台启动和自动恢复默认不会自动启动 ChatGPT 或 WorkBuddy；用户在网页或 ClawBot 中明确选择桌面终端或任务时，仍可按需打开对应应用。只有需要在 daemon 启动阶段自动打开桌面应用时，才传入 `--open-desktop-apps`。

daemon 会：

1. 在连接具体 Agent 前先启动移动网页；
2. 从物理网卡选择局域网 IPv4 地址；
3. 从 `WERELAY_MOBILE_PORT`（默认 `4396`）开始监听；
4. 端口冲突时尝试后续端口；
5. 使用本机保存的移动访问密码保护网页。

本机验证：

```bash
curl -fsS http://127.0.0.1:4396/health
```

实际端口以 `~/.werelay/bridge.log` 中的 `codex_mobile_started` 为准。

### 首次密码设置

启动时终端打印的是局域网基础地址，不携带首次设置密码所需的 setup 授权。新用户应在 ClawBot 中：

1. 发送“任务”；
2. 进入一个任务；
3. 发送“状态”；
4. 从返回的任务链接打开网页并设置访问密码。

任务完成通知中的链接也可以用于首次设置。setup 链接属于敏感短期授权，不要转发、截图或提交到 issue。

完整步骤见 [局域网移动网页快速开始](../使用指南/局域网移动网页快速开始.md)。

## 公网 Relay 模式

### 数据流

```text
手机浏览器
  ↓ HTTPS
公网 WeRelay Relay
  ↑ HTTPS 长轮询（电脑主动发起）
电脑上的 WeRelay daemon
  ↓ 本机 Agent 协议
Codex / Claude / WorkBuddy / DeepSeek Harness / 更多 Agent
```

公网服务器不会主动连接电脑的本地端口。电脑像 ClawBot 一样主动取回任务级请求，再主动提交结果。因此不需要也不允许使用 cloudflared、SSH `-R`、frp、ngrok 等通用端口穿透。

Relay 接受的只是 WeRelay 移动接口，例如：

- Agent 与任务列表；
- 最近消息和运行状态；
- 发送消息和附件；
- 审批与用户输入；
- 停止任务；
- 排队消息操作。

真实任务、上下文、工具、权限和项目文件始终由用户电脑上的 Agent 持有。

### 最小配置

服务器需要：

- Linux；
- Node.js `>= 24`；
- 指向服务器的域名；
- 有效 HTTPS 证书；
- Nginx 或 Caddy；
- 公网只开放 `80/443`。

服务器和电脑必须配置相同的：

```text
WERELAY_RELAY_DEVICE_ID
WERELAY_RELAY_DEVICE_TOKEN
```

电脑还需要：

```text
WERELAY_RELAY_URL=https://relay.example.com
```

Relay 内部默认监听：

```text
127.0.0.1:14396
```

正式部署步骤、持久化、验收和回滚见 [公网 Relay Agent Runbook](../使用指南/公网Relay配置与验收.md)。GitHub 仓库和本地打包产物包含：

```text
deploy/systemd/werelay-relay.env.example
deploy/systemd/werelay-relay.service.example
deploy/nginx/werelay.conf.example
```

## 公网模式运行行为

连接后：

- 本地移动网页继续运行，仍可局域网直连；
- daemon 主动连接 Relay，服务器不反向拨入电脑；
- 完成通知使用 HTTPS 短任务链接；
- 非 GET 操作使用命令 ID 和本地 journal 去重；
- 设备预热只允许读取 GET 接口，不能发送消息、审批、停止任务或执行其他写操作；
- Relay 仅在内存中保存有界的预热响应，不保存完整任务数据库：单条响应最多 `2 MB`，每个浏览器会话最多 `12 MB`，最多保留 `4` 个会话，连续 `30` 分钟未刷新后失效；
- 已认证浏览器可先显示最近一次验证过的有限缓存，再静默刷新；
- 只有经过电脑验证的浏览器登录会话可以读取对应缓存，缓存不能绕过移动访问密码；
- 电脑离线且没有缓存时，页面明确等待电脑连接；
- 电脑离线时不得自动创建独立 CLI、ACP 或替代任务。

公网网页与电脑处于同一网络时，可以尝试安全切换到局域网高速连接。该能力依赖公网出口一致、局域网互访和浏览器策略；失败时保留公网连接，不影响基本使用。

## 验收标准

只有以下项目都通过，才算公网部署完成：

1. 服务器本机 `/health` 返回 `ok:true`；
2. Relay 只监听服务器回环地址；
3. 公网 HTTPS `/health` 正常且证书有效；
4. 电脑连接后 `deviceOnline:true`；
5. 外部网络能打开登录页；
6. 登录后能读取真实 Agent、任务和最近消息；
7. 手机消息进入电脑端同一个任务；
8. 支持的审批、停止、排队和附件能力可以同步；
9. 电脑停止 daemon 后，页面明确显示离线；
10. 离线时没有创建替代会话。

`/health` 正常但真实消息没有进入同一个桌面任务，不算通过。

## 安全要求

1. **不直接发布本机端口。** 不使用通用隧道把用户电脑的 `4396` 暴露到公网。
2. **Relay 只监听服务器回环地址。** 公网只暴露 HTTPS 反向代理。
3. **分离两种凭据。** 设备密钥用于电脑与 Relay；移动密码用于浏览器登录。
4. **秘密不进入 URL。** 设备密钥不能放在 URL、命令行参数、Git、截图或 issue 中。
5. **限制文件权限。** 服务器环境文件使用 `0600`，状态目录使用 `0700`。
6. **只保留一个 daemon owner。** 不增加根据 `deviceOnline` 强制重启 daemon 的第二 watchdog。
7. **桌面端保持唯一任务 owner。** 不可用时明确报错，不创建隐藏会话。
8. **服务器和电脑同步升级。** 升级后重新验证健康、真实消息和离线行为。
9. **预热缓存只读、有界且不落完整任务库。** 只允许 GET；单条最多 `2 MB`，每个浏览器会话最多 `12 MB`，最多保留 `4` 个会话，连续 `30` 分钟未刷新后失效；只有经过电脑验证的浏览器登录会话可以读取，不能绕过移动访问密码。
10. **短链接状态文件保持私有。** 只保存短码与任务映射，不保存消息正文或 Cookie；文件权限保持 `0600`，所在目录保持 `0700`，并由受限 Relay 服务账号持有。

更多边界见 [安全策略](../../SECURITY.md)。

## 常见故障

### 公网页面显示电脑离线

- 确认电脑上的 `werelay` daemon 正在运行；
- 确认三个 `WERELAY_RELAY_*` 变量进入了真实 daemon 环境；
- 确认服务器和电脑的设备 ID、设备密钥完全一致；
- 查看 `~/.werelay/bridge.log` 中的 `relay_client` 记录；
- 检查公网 `/health` 的 `deviceOnline`。

### Relay 提示设备认证失败

服务器和电脑的 `WERELAY_RELAY_DEVICE_TOKEN` 不一致。安全更新两端配置后，分别重启 Relay 和唯一 daemon。

### 公网页面能打开，但 API 超时

检查：

- 本机移动网页 `/health`；
- Relay 长轮询是否被代理提前断开；
- `proxy_read_timeout` 和 `proxy_send_timeout` 是否至少为 `120s`；
- 电脑是否休眠；
- 服务器与电脑时钟是否严重偏差；
- 公网页面显示的是缓存，还是已经完成在线回读。

### 同一局域网没有自动切换到高速连接

公网模式仍可正常使用。局域网加速依赖手机和电脑公网出口一致、局域网地址可互访，以及浏览器允许从 HTTPS 页面访问局域网 HTTP；任一条件不满足时都会保留公网连接。

更多排查见 [问题排查](../使用指南/问题排查.md#werelay-移动网页打不开)。
