# 通用会话组件

网页任务台使用 `src/web/chat-components/` 中的无框架组件，不再自己构造气泡、工具文本或输入框内部界面。保留原来的 HTML/CSS 语言，不引入 React、额外网络请求或新的构建工具。

## 职责边界

| 组件 | 输入与能力 | 不负责 |
| --- | --- | --- |
| `createText(options)` | 安全文本转义、Markdown、代码/命令折叠、工具分组、执行进展；本地链接转换由 `resolveLink` 注入 | 请求本地预览服务、任务状态判断 |
| `createMessageBubble(options)` | `render(view)` 返回气泡节点；角色、连续回复、图片、来源、模型/时间、送达提示、复制/重试/图片预览回调 | 消息清洗、用户回执匹配、稳定身份与缓存、重发 |
| `createComposer(root, options)` | 完整文字/图片/队列输入框、模型分组、推理与权限菜单、发送/停止状态、渐变/运行动画、快捷键、粘贴与自适应高度 | 上传、权限授权、模型 RPC、排队策略、草稿存储、任务提交 |

任务台的 `codex-mobile-web.ts` 继续持有真实任务数据。它把数据映射成展示模型，通过组件方法更新界面；用户操作由回调返回原有业务流程。去重、消息持久化、失败重试、下一轮模型切换和附件保存顺序都不交给组件。

## 入口与资源

- `renderChatComposerHtml(prefix?)`：输出完整输入框。默认保留任务台已有 ID；同页多实例必须使用不同的前缀。
- `CHAT_COMPONENTS_JS`：浏览器脚本，声明 `WeRelayChatUI`。执行脚本本身不访问 DOM，也不请求网络；创建组件时才使用传入节点的 `ownerDocument`。
- `CHAT_COMPONENTS_CSS`：独立页面样式。外层添加 `class="werelay-chat"`，可覆盖 `--page`、`--text`、`--green`、`--thread-max` 等变量。独立模式输入框处于普通文档流；宿主可覆盖定位。
- `styles.ts`：原任务台按原级联位置组合共享样式片段；因此固定底部、安全区、窄屏和深色模式规则不因抽取改变。
- `CODEX_MOBILE_APP_JS`：仅任务台控制器，方便测试隔离。对外仍提供原 `CODEX_MOBILE_JS`，由组件脚本和控制器组合，资源版本哈希与 Android 资源导出仍覆盖完整内容。

组件 CSS 使用 `message-*`、`composer-*` 等原有类名，并非 Shadow DOM 隔离。嵌入已有页面时应避免同名类冲突；JS 的输入框查询则限定在实例根节点内。

## 输入框调用契约

```js
const composer = WeRelayChatUI.createComposer(formElement, {
  actions: {
    onSubmit(event) { /* 宿主根据当前状态发送、排队或停止 */ },
    onInput(event) { /* 保存草稿，然后更新按钮状态 */ },
    onFiles(files) { /* 校验并保存附件；组件不会自行上传 */ },
    onModelSelect(modelId) { /* 宿主确认后重新 renderModel */ },
    onSettingSelect(kind, value) { /* kind 为 reasoning 或 permission */ },
    onResize(height) { /* 可更新正文的底部留白 */ }
  }
});
composer.setValue("待发送文字");
composer.updateAction({
  enabled: true, hasContent: true, stopMode: false,
  stopRequested: false, sending: false, queueBusy: false, beamActive: true
});
```

主要方法：

- `getValue()`、`setValue(text)`、`resize()`；程序写入不自动触发提交或草稿回调。
- `renderImages(images)`：每项使用 `id`、`previewUrl`、`fileName`。增删数据由宿主完成后重新渲染。
- `renderQueue(messages, { busyId })`：支持已确认与乐观排队卡；回调为 `onQueueSteer(id)`、`onQueueEdit(message)`、`onQueueDelete(id)`。
- `renderNotice({ visible, text, retrying })`：在输入框上方显示常驻连接提示，与排队区域对齐；重试由 `onNoticeRetry()` 回调交给宿主，连接中禁用重复点击，不清空草稿或队列。宿主确认恢复后再隐藏，不能由提示计时器或缓存任务列表移除。
- `renderModel(view)`：`visible/open/label/title/canChange/changing/retry/value/options/activeGroup/key`；`options` 每项包含 `id/label/description/group`。宿主通过 `onModelGroup(group)` 与 `onToggleMenu(kind)` 控制分组和开合。
- `renderSession(view)`：基础控制字段同上，`groups` 每项包含 `kind/label/value/disabled/options`。推理强度选项不显示英文说明。菜单内容未变化时保留原节点，避免轮询打断点击。
- `closeMenu(kind)`：隐藏指定菜单；外部点击会调用 `onCloseMenu(kind)`，宿主应同步自己的开合状态。
- `updateAction(view)`：仅呈现 `send/pending/running/stopping`，不决定实际任务是否运行。宿主决定是否显示停止、是否禁用与是否显示输入框渐变。
- `part(name)`：获得当前实例内的兼容 DOM 句柄，供原有草稿、选区和焦点操作渐进迁移。
- `destroy()`：卸载宿主时必须调用；移除实例/文档事件、取消动画与待执行的尺寸回调。不会删除宿主内容或数据。

补充回调：`canAttach()`、`onInsertText(text)`、`onImageRemove(id)`、`onOpenImage(url, alt)`、`onEscape(event)`。需要取消浏览器默认行为时，宿主在 `onEscape` 中调用 `preventDefault()`。未提交的内容仍由宿主持有，组件不会清空或后台发送。

## 文本与气泡调用

```js
const text = WeRelayChatUI.createText({
  resolveLink(target) { return { href: target, localPreview: false }; }
});
const bubble = WeRelayChatUI.createMessageBubble({
  document, text,
  actions: { onRetry(clientId) {}, onCopy(text) {}, onOpenImage(url, alt) {} }
});
const row = bubble.render({
  id: "message-example", message: { role: "assistant", text: "已完成" },
  text: "已完成", continues: false,
  footer: { model: "示例模型", time: "完成于 18:00" }
});
container.appendChild(row);
```

失败提示可传 `delivery: { text, failed, copy, retryLabel }`；跨任务来源传 `sourceLabel` 与 `message.sourceTask`。组件只接受文本，不接受任意 HTML 插槽。图片地址应由宿主提供已授权的地址，组件不会绕过认证。`text.renderProgressList(document, items, adapterLabel)` 接受宿主已确认状态的进展项，默认折叠较早的已完成条目；`renderPendingIndicator(document, label)` 负责回复末尾的执行中提示，是否展示仍由宿主判断。

## 独立示例与验证

运行 `bun scripts/examples/chat-components.mjs` 可在忽略目录 `tmp/chat-components/example.html` 生成独立页面。生成物内联组件脚本与样式，可离线打开；包含两个互不串扰的输入框、消息气泡、失败操作、工具折叠、队列、图片和模型设置。所有“发送/停止”只操作合成数据，不请求真实 Agent。

自动化覆盖：组件无任务台依赖加载、多实例 ID/草稿隔离、销毁、菜单稳定性、队列/图片回调、发送状态、HTML 转义和折叠结论保留。任务台仍运行原有消息持续显示、去重、排队、模型、草稿和移动资源测试。浏览器使用合成夹具验收，不自动给真实 Agent 或 ClawBot 发消息；线上与真实手机体验由统一部署后的用户验收。
