# WeRelay 0.3.7

## 这次更新

- 长任务处理时，手机网页会持续补充当前正在执行的步骤、命令和计划，不再长时间只显示“正在处理”和计时；即使历史读取使用了加速缓存，也会同时接上真实任务的最新进展。
- 任务已经结束后，网页会及时清除过期的运行状态，模型、推理强度和权限范围控件会按真实任务状态重新开放，不再被旧的“运行中”标记长期锁住。
- 权限入口在加载和暂时读取失败时仍会保留，并明确显示“获取中”或“暂不可用”，不会突然从输入区域消失。

- 手机网页现在可以直接查看并切换当前任务的权限范围。Codex、DeepSeek Harness 和 WorkBuddy 会沿用各自真实任务的权限设置；任务正在处理时不能切换，选择“完全访问”还会再次确认，避免误触后扩大权限。
- ClawBot 的任务列表会把网址、邮箱、文件名和本地路径按普通文字显示，较长的任务名和项目名会自动收短；列表更清楚，也不会再被微信误识别成可点击链接。
- 手机网页首次打开任务看板时会先展示本地已有缓存，再在后台安静更新；即使任务看板本身尚无缓存，也会先用各终端最近保存的任务补齐，不再先空白或只显示骨架屏。
- 在手机网页里打开电脑本地页面或当前项目文件时，会先显示“正在部署到服务器”的真实进度，每次点击都重新读取最新内容，完成后自动打开一份临时公网预览。预览只读取当前项目文件或电脑回环地址的同源静态资源，默认 15 分钟失效，不会把电脑端口直接开放到公网。
- 本地页面依赖实时接口、长连接或其他电脑后端时，临时预览可能只能展示静态部分；需要查看最新改动时重新点击原链接即可。
- 公网网页正在读取较慢的任务时，新建任务、发送消息和其他修改操作会优先送到电脑，不再被旧的读取请求堵在后面而等待几十秒甚至超时。
- 网页新建任务遇到短暂网络错误或服务器超时，会安全重试一次并沿用同一个创建身份；即使电脑已经完成第一次创建，也只会得到同一条任务，不会增加重复空任务。
- 新任务第一轮结束后会更稳妥地把任务交还给 Codex Desktop；第一次接力遇到占用时会自动再试，任务已经结束后也不会重新抢占，减少“已在另一个应用中打开”。
- 模型容量暂时不足时，网页会明确显示“模型暂时繁忙”，并提示稍后重试或切换模型，不再笼统显示没有生成回复。
- 移动网页恢复到之前创建失败的新任务草稿时，再次点击“新建任务”会沿用原来的项目和草稿身份立即重试，不再只是回到旧的失败页面。
- 创建失败时，消息下方和空任务页面会显示简短、经过安全处理的真实原因，并保留明确的重试入口，方便判断是终端未连接、任务正忙还是其他问题。
- 尚未失败、只是还没有发送内容的新任务草稿仍会直接恢复，不会因为再次点击“新建任务”而重复创建。
- 在移动网页新建 Codex 任务后，可以直接把第一条文字和图片一起发出；网页会等这条消息真正进入新任务后再交给电脑端，不再出现任务已经创建却提示“创建失败”。
- 公网请求较慢、短暂超时或点击重试时，会继续使用同一个新任务，不会重复生成多个空任务；只有确认创建失败后，才会允许重新尝试。
- 新任务的第一条消息会始终在同一条真实 Codex 任务中开始处理，完成后仍可从电脑 Codex Desktop 继续进入这条任务。
- ClawBot 现在会记住最近一次明确展示或通知的任务；直接回复内容时，会继续发送到那条任务，即使期间切换了终端或 WeRelay 重启，也不会悄悄发到别的会话。
- 任务消息会带稳定序号，可以直接回复序号进入任务，也可以发送“任务6：继续处理”把内容准确送到对应任务；审批或补充信息仍会优先处理，不会把纯数字误发给模型。
- 发送 `/h` 或 `/help` 可以随时查看精简的 ClawBot 操作说明，即使尚未选择终端也能使用。
- 公网网页只会在你真正查看或刷新内容时向电脑取新数据；页面没有操作时不会自己反复读取任务列表，关闭页面后也不会留下后台扫描。
- 打开任务看板或最近任务时，不会为了读取目录自动启动 Codex，也不会扫描大量旧任务；电脑端更不容易出现高占用、暂时离线或网页一直停在“正在读取”。
- 某个终端暂时没有响应时，任务看板会先显示其他可读取的任务，不再让整个页面跟着等待很久。
- 微信向已有 Codex 任务定向发送消息时，会优先连接真实桌面任务；即使只读任务索引启动较慢，消息也不会因此发送失败。
- 从 ClawBot 明确切换到已打开的 WorkBuddy 时，如果旧进程尚未接入桌面任务接口，WeRelay 会自动识别旧版桌面接入、重启应用并等待桌面任务接口真正就绪，再恢复原任务，不再因启动时序直接提示切换失败。
- WorkBuddy 的提问会按“需要补充信息”展示问题与选项，不再误当成工具审批；回复后会把答案交回原任务继续处理，长时间等待回答也不会被两分钟超时打断。
- Codex、WorkBuddy 和 CodeBuddy 的任务列表会优先显示电脑端的用户重命名或生成标题，不再退回首条消息或任务编号；其他终端也已按各自原生标题字段核对。
- CLI 终端的普通任务不再把工作目录文件夹名显示成项目名，也不会因此被拆成多个伪项目分组；只有能确认是用户显式重命名的 CodeBuddy、Reasonix 或 ACP 任务才保留项目标签。
- WorkBuddy 上次打开的任务已经删除或桌面运行时无法恢复时，会自动清除失效记录并立即保持终端已连接，不再依次探测多个最近任务而造成几十秒等待；任务列表和历史仍可直接查看，用户进入或发送指定任务时再精确接入。
- 在 ClawBot 发送“任务”或切换终端后，会先立即回复“正在获取中”，再发送完整列表；全终端列表标题也精简为“全部任务”。
- 从 ClawBot 向任一终端任务发送消息后，会立即说明消息是已经发送、进入队列、重复而未发送，还是因为任务正忙没有发送，并附上对应任务链接，避免因为没有反馈而重复操作。
- 全终端和单终端任务列表会用同一套“处理中 🟢”标记，便于快速确认任务仍在运行。
- 独立打开的 Grok CLI 任务现在也会读取 Grok 自己的会话事件，任务正在执行时显示“处理中 🟢”，结束后恢复空闲；不再因为没有接入 WeRelay Companion 就始终看起来未运行。
- 网页现在可以在 Codex 和 DeepSeek Harness 任务中直接查看并切换推理强度；任务正在处理时会暂时禁止切换，完成或停止后即可调整。
- 没有手动选择、会话也没有报告推理强度时，网页会显示“跟随会话”，不再猜测一个默认值；切换模型时只保留新模型仍支持的会话强度。
- 每次打开终端下拉列表，都会重新汇总各终端的真实任务状态；正在处理的终端显示绿色呼吸点，任务结束后会自动恢复为空闲，不再因只读取当前终端而漏掉其他终端。
- 移动网页中的 DSH 现在显示完整名称“DeepSeek Harness”。
- DeepSeek Harness 会按任务真实所在目录恢复项目分组，兼容 macOS、Linux 和 Windows 路径，也可以重新从项目页直接新建任务。
- Codex 正在回复时，从网页发送的后续消息会进入原任务队列，并在当前回复结束后继续处理；长回复的完成通知也会分段完整发送，不再只保留开头。
- 网页历史不再显示 Codex Desktop 本来会隐藏的 `[tool_use]`、`[tool_result]` 内部占位记录；旧缓存、加速历史和实时分页都会使用同一过滤规则，正常正文中提到这些词时仍会保留。
- 手机上长按左侧任务后，重命名和复制任务 ID 菜单会稳定保留，不再因松手后的点击或右侧正文误选中而立即消失；菜单按钮也扩大为更容易点击的触控尺寸。
- 在手机网页中长按单条消息并选择“全选”时，只会选中这一条消息的正文，不再把侧栏、页面标题或其他消息一起选中。
- 网页已经看到最新 AI 回复或服务端确认任务结束时，会立即停止正文末尾的处理中动画，不再让已完成任务继续显示等待状态。
- 打开包含很长历史记录的 Codex 任务时，旧图片查找和运行状态检查都有明确读取上限，最近任务中的输入图片仍可正常显示。
- DeepSeek Harness 的模型菜单会按来源分组展示，输入框上方的模型、推理强度和权限标签也更简洁；较长的模型名称会完整换行显示，不再被省略号截断。
- DeepSeek Harness 任务当前使用的模型已经下线或不可用时，仍可以正常切换到其他可用模型；不会再出现任务既不能发消息、也不能换模型的卡死状态。
- 手机网页新建的 Codex 任务会保持在新任务所属的项目里，不会被错误归入其他项目。
- Claude Code、DeepSeek Harness 等终端的消息会显示真实任务名，不再显示内部会话编号。

## 是否需要操作

- 不需要重新配置；安装 0.3.7 正式版后重启 WeRelay 即可。
- 从 0.3.6 或更早版本升级会自动沿用现有配置和数据，无需重新登录。
- 如果微信完成通知仍提示需要新消息，请先在微信里给 ClawBot 发送一条普通消息，以刷新微信会话。
