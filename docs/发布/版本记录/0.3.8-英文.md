# WeRelay 0.3.8

Release date: 2026-09-04

## What’s new

- After a message is sent from the mobile web app, the computer continues processing and delivering it even if the page is closed. Multiple messages sent to the same task keep their original order.
- The mobile model picker now lets you choose a provider first and then a model. Reasoning effort and access permission share one concise control that shows readable states such as “Medium · Full access.”
- The composer now has a subtle animated beam while continuing to respect the system’s reduced-motion preference.

## Fixes

- Fixed messages disappearing, being submitted twice, or arriving out of order when the page closed, the network briefly disconnected, or the computer responded slowly. Messages that still cannot be submitted remain visible, can be copied or retried, and repeated failures can notify you through ClawBot.
- Fixed cases where the second level of the mobile model menu could not be selected. When no reasoning effort has been chosen manually, the interface now clearly shows that it follows the current session.
- Fixed the visible task transcript briefly becoming blank while switching terminals or reconnecting. Existing content now remains visible while the latest content is refreshed in the background.

## Upgrade notes

- No new login or configuration change is required.
- Mobile pages that are already open will refresh automatically after detecting the new app version.

## Known limitations

- Background delivery after leaving the page still requires WeRelay to keep running on the computer. Messages are retained while the computer is temporarily offline and wait for the connection to recover.
- Available models, reasoning efforts, and permissions still depend on what the active terminal and task actually support.
