# WeRelay 0.3.15

Release date: 2026-10-09

## What's new

- The mobile task dashboard now includes a session organizer grouped by project and activity. Suggested titles are applied only after explicit confirmation; task content is never changed automatically.
- More terminals expose their actual model and reasoning choices. Unsupported settings are explained rather than presented as guessed capabilities.
- Pi integration continues the same visible desktop task from mobile or WeChat text messages, without silently creating another conversation.

## Fixes

- Continuing a Codex task that is not yet loaded on the desktop allows time for owner discovery. The original task is opened only after its absence is confirmed, reducing premature delivery failures.
- Improved mobile message confirmation, deduplication, and recovery. Uncertain delivery is not immediately treated as a failure and resent.
- Improved task-completion synchronization to reduce cases where the web page remains waiting after a reply.

- Updated the communication component and related dependencies to fix security vulnerabilities found during release checks.

## Upgrade notes

- Run `/reload` in an already open Pi window to load the new settings support. No session-file copying or replacement task is required.
- Sign in before using the session organizer. Terminals without rename support do not offer a save action.
- Source and installation archives are distributed through GitHub, not the public npm registry.

## Known limitations

- WeChat may intermittently reject outgoing notifications. Original-task messaging and completion delivery were verified, but continuous reliability of every push is not guaranteed. Sending a new ClawBot message may refresh the reply context; no fixed validity period is promised.
- WorkBuddy includes cross-task approval observation and notification batching while unlocked, but real approval and lock-screen scenarios have not completed device acceptance. Full availability is not claimed.
- Public access works; the complete automatic LAN handoff still needs acceptance testing. Continue using the public address if handoff fails.
- Pi image input, approval forwarding, and invoking Pi's own slash commands from WeChat remain unsupported.
