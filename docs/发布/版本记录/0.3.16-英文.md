# WeRelay 0.3.16

Release date: 2026-10-13

## Fixes

- Pi task catalogs and history no longer require opening an empty terminal. Sends attach the exact existing writer; unavailable or ambiguous owners are reported instead of creating a replacement conversation.
- Improved identification and reconnect of Pi Desktop native sessions, including several native tasks in one sidecar. Desktop-private sessions are not included.

- A real new WeChat message received during an existing recovery pass schedules another check after that pass, reducing missed recovery opportunities with a fresh reply context.
- Notifications stopped because of age or backlog capacity retain undelivered receipts and are not resurrected as new notifications after restart.
- Capacity pressure preserves in-flight notification checkpoints, reducing repeated delivery of already-confirmed parts during recovery.
- Dispatch acknowledgements now say that WeRelay will attempt a WeChat notification and suggest checking the dashboard if it does not arrive.

## Maintenance

- Updated README branding and clarified that WeChat needs no self-hosted server, while LAN and public access are two connections to the same dashboard.
- Corrected automated dependency updates to match the committed dependency lockfile.
- Authenticated task connections can query pending, delivered or undelivered completion receipts. No new dashboard notification-status button is included.

## Upgrade notes

- No new pairing or replacement task is required. The service briefly reconnects during the upgrade.
- Run `/reload` in existing Pi CLI windows. Desktop native runtimes must reload the extension; WeRelay does not force-restart the app.
- If WeChat persistently rejects notifications, send ClawBot a real new message to refresh the reply context or read the result in the dashboard.

## Limitations

- This improves persistence and recovery, not guaranteed upstream push acceptance. No synthetic conversation or empty keepalive messages are introduced.
- Unknown send results still retain duplicate protection; end-to-end exactly-once delivery is not guaranteed.
- Existing acceptance gaps for WorkBuddy approvals and lock-screen behavior, automatic LAN handoff, and Pi images/approvals remain.
