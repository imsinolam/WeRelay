# WeRelay 0.3.17

发布日期：2026-10-20

## 新增与改善

- 电脑与公网中继优先使用实时连接，连接不可用时自动退回原来的方式；手机仍可继续原任务，无需另开对话。
- 微信发现 GitHub 有正式新版本时，会提示当前版本、可更新版本和说明链接。只提醒，不会自动安装或重启。
- 微信任务列表显示运行数量，并可按需要增加展示条数；长回答分段发送后仍保留对应任务编号。
- 手机任务看板更紧凑，正在运行、等待审批或等待输入的任务不再误入最近完成列表。
- 手机输入区用动态圆球表示发送、运行和停止过程；电脑离线时保留清楚的状态提示。
- Pi 可在同一个已连接窗口中新建任务，并在新建前读取可用模型；没有可用原窗口或窗口有未发送内容时会明确提示，不另开隐藏对话。

## 通知恢复

- 微信恢复后，最近三分钟完成的通知会自动尝试发送；更早但未超过一小时的通知先询问，回复“推送”或“补发”后再发送。
- 超过一小时的旧完成通知不再补发，避免积压内容集中打扰。

## 升级说明

- 无需重新配对或创建任务，升级时连接会短暂重建。
- 已打开的 Pi 窗口请执行 `/reload` 加载扩展更新。
- 微信新版本提醒需先升级到本版；旧版本不会因为 GitHub 更新而自动获得提醒能力。
- 若微信拒绝通知，请向 ClawBot 发送真实消息刷新回复上下文；结果仍可在任务台查看。

## 已知限制

- 微信仍受平台回复上下文限制，不保证任意时间都能主动通知，不使用虚构对话保活。
- 新实时连接已通过公网收发验证，长期运行与睡眠恢复仍需观察；不能承诺任何异常下都绝不重复。
- Pi 同窗口新建已完成真实组件验证，本轮未重新验证可见窗口内的完整发送、新建交互、图片与审批。
- 原有 WorkBuddy 审批与锁屏、自动局域网交接等验收缺口仍存在。
