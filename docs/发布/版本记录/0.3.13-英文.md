# WeRelay 0.3.13

Release date: 2026-09-22

## Improvements

- The mobile web app now keeps a continuous message timeline from sending through terminal acceptance, execution and completion, without treating slow desktop acknowledgements as failures or showing duplicate messages.
- New tasks can select a model and reasoning effort before the first message is sent, while existing sessions keep their current settings.
- Messages arriving from another Codex task retain their source and timestamp instead of being mistaken for a new local send.
- DeepSeek Harness connections, task recovery and completion delivery are more resilient, and slow task discovery no longer blocks the web app, WeChat or other terminals.

## Fixes

- Fixed the computer appearing offline while it was still running. Slow background checks are isolated from the main connection, and the most recent usable task list remains available when a refresh fails.
- Fixed WeChat question replies reaching the wrong task, commands becoming unresponsive during recovery, and non-Codex completion notices being lost after restart.
- Fixed approval cards leaking across tasks, completed state attaching to an older message, sent messages briefly disappearing, and stale pending records blocking the composer indefinitely.
- WeChat task lists now send their content and instructions separately. New short links avoid trailing symbols that WeChat could truncate, while previously issued links remain valid.
- WorkBuddy can show its task list before a terminal connection is established, and Grok can create a task from the Recent group when no project is available.
- Mobile tasks default to writable project permissions, and internal desktop transport wrappers are no longer shown in user messages.

## Upgrade notes

- No re-pairing or task migration is required; restart WeRelay after upgrading.
- If WeChat reports that its sending context has expired, send ClawBot one normal message to refresh the session before continuing.
- A message still awaiting terminal confirmation after one hour leaves the pending list and returns to the transcript with its content preserved, where it can be copied, edited and resent, or removed locally.

## Known limitations

- Recovery after computer sleep, a network interruption or a long WeChat idle period can still take a short time. An expired WeChat context requires a fresh inbound message.
- Before WorkBuddy is connected, its task list is read-only. Entering the terminal establishes the connection and enables create, rename and send actions.
- This release continues to use application-level HTTPS long polling for the public Relay and does not expose a general-purpose network tunnel.
