# WeRelay 0.3.17

Release date: 2026-10-20

## Changes

- The computer prefers a real-time connection to the public relay and falls back to the previous transport when unavailable. Mobile users continue the original task without a separate conversation.
- WeChat can notify you when GitHub publishes a newer stable release, with installed and available versions and a release link. It does not install updates or restart services automatically.
- WeChat task lists show the running count and allow custom list sizes. Split long replies retain their task number.
- The mobile task board is more compact. Running tasks and tasks awaiting approval or input no longer appear as recently completed.
- An animated orb indicates sending, running and stopping. Offline status remains visible.
- Pi can create a task in the same connected window and list models before creation. Missing owners and unsent drafts produce an explicit warning instead of a hidden conversation.

## Notification recovery

- On recovery, completion notifications from the last three minutes are attempted automatically. Older notifications up to one hour require confirmation with “推送” or “补发”.
- Notifications older than one hour are not replayed.

## Upgrading

- No re-pairing or replacement task is required. Connections briefly reconnect during an upgrade.
- Run `/reload` in existing Pi windows to load the updated extension.
- Install this release first to receive future update reminders; publishing on GitHub cannot add this capability to an older process.
- If WeChat rejects notifications, send a real message to ClawBot to refresh its reply context, or read the result in the task console.

## Known limitations

- WeChat still depends on platform-approved reply context. Unrestricted proactive delivery is not guaranteed; no synthetic conversations are used for keepalive.
- Public real-time message delivery has been verified. Long-running and sleep/wake recovery need further observation; exactly-once delivery is not guaranteed for every failure mode.
- Pi same-runtime task creation passed real component validation. This round did not revalidate full visible-window sending, new-task interactions, images or approvals.
- Existing acceptance gaps for WorkBuddy approvals/lock-screen use and automatic LAN handoff remain.
