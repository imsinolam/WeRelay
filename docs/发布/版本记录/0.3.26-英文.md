# WeRelay 0.3.26

Date: 2026-10-30

## Changes

- Prepare a Pi Desktop connector plugin when native control is unavailable. After explicit installation and permission, mobile access continues the original Desktop task without a separate CLI owner.
- Restore composer availability after completed tasks and release HTTP waits when a trusted receipt confirms acceptance. Uncertain submissions retain their original identity and attachments instead of replaying automatically.
- Add opt-in server support for Android vivo push registration, refresh and removal. It remains inactive without vendor credentials and does not affect web or WeChat.
- Correct public-origin matching and original-task routing in push notifications. Approval notifications do not transmit command text.

## Upgrade

Refresh the web page; WeChat pairing is unchanged. If Pi Desktop is not connected, run `werelay-pi-desktop-enable` and follow its instructions to install and authorize the plugin. No application restart or approval bypass is performed automatically.

This deployment updates WeRelay and the public relay, not the Android application. Vendor push requires a compatible app and credentials, neither of which is installed or enabled here.

## Limitations

The plugin currently supports macOS/Linux only. Real Desktop, attachment and ClawBot acceptance is user-owned. vivo credentials and real-device delivery have not been exercised; CONTENT notifications are subject to the vendor's 07:00–23:00 window and rate limits, without guaranteed night-time catch-up or cross-channel deduplication. Previously observed relay disconnect/recovery is not claimed fixed.
