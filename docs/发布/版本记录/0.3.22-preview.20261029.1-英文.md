# WeRelay 0.3.22-preview.20261029.1

Preview date: 2026-10-29

## Changes

- Preserve sidebar task caches when switching agents and order agents by actual recent message activity, not task browsing.
- Add a separate Pi Desktop entry connected to the existing local owner. Requires its authenticated local control interface; never falls back to a replacement CLI session.
- Add a web task link to ClawBot task lists and simplify usage hints.
- Back off repeated task-monitor failures and avoid automatically resubmitting known unavailable inputs while preserving message contents.
- Allow selecting the next-turn Codex model while a reply is running; connect Pi model controls to an existing integrated window.
- Export shared taskboard resources and provide an optional signed Android update endpoint. No APK or signed update artifact is distributed by this deployment.

## Usage

- No new login or pairing required; existing tasks remain unchanged.
- Existing Pi windows need an idle `/reload` or normal reopen to load the extension. Running windows are not forcibly closed.
- The user owns live Agent and ClawBot message, approval and reply-delivery acceptance. The deployment agent performs service, web and connection checks without sending acceptance messages.

## Limitations

- Pi Desktop requires its authenticated loopback control interface. Approvals and questions remain on the Desktop app; missing control does not trigger a substitute session.
- Android installation, signing keys and physical-device acceptance are separate. Without a configured bundle, the update endpoint remains disabled.
- Includes prior plain-text draft sync and Pi running-state changes. Simultaneous multi-device draft sends are not claimed race-free.
- WeChat push still requires a valid reply context. Existing Codex owner readiness and catalog-read issues are not claimed fixed.
- This is an experience preview, not a formal GitHub release.
