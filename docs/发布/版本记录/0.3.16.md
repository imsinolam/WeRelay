# WeRelay 0.3.16

发布日期：2026-10-13

## 修复的问题

- Pi 任务列表与历史读取不再要求先启动一个空终端。选择任务后，消息只交给对应原窗口；连接不可用或有多个窗口同时持有原任务时会明确提示，不另建对话。
- 改善 Pi Desktop 复用的原生会话识别与重连，并支持同一个桌面进程中的多个原生任务分别接入。Desktop 自建独立会话不在本次支持范围。

- 微信收到新消息时，即使正在处理上一轮通知补发，也会在处理结束后再检查一次，减少新回复上下文已经到达却未及时恢复通知的情况。
- 因等待过久或积压过多而停止补发的完成通知，会保留未送达记录；重启后不再把这些旧通知当成新的通知重新发送。
- 通知积压较多时，保留正在发送的通知及其已发送部分，减少恢复时重复发送已经确认送达内容的风险。
- 发送提示改为“完成后会尝试在微信通知你”，未收到时可以打开任务台查看结果，避免把任务已开始误解为通知一定能够送达。

## 维护更新

- README 更新品牌图示，说明微信接力无需自建服务器，以及同网和外网任务台的连接关系。
- 修正自动依赖更新配置，使其与项目使用的依赖文件一致。
- 登录后的任务连接可以查询完成通知处于待发送、已送达还是未送达状态；本次没有增加网页通知状态按钮。

## 升级说明

- 无需重新配对或创建任务。升级时服务会短暂重连。
- 已打开的 Pi CLI 请在原窗口执行 `/reload` 加载更新。Pi Desktop 原生任务也需重新加载扩展；WeRelay 不会强制重启桌面应用。
- 若微信持续拒绝通知，请向 ClawBot 发送一条真实消息刷新回复上下文；也可以直接在任务台查看结果。

## 已知限制

- 本次改善的是通知保存和恢复，不保证微信始终接受主动推送，也不通过虚构对话或空消息保活。
- 发送结果不明确时仍保留防重复保护；这不是端到端绝不重复的保证。
- 原有 WorkBuddy 审批与锁屏、自动局域网交接和 Pi 图片/审批等验收缺口仍存在。
