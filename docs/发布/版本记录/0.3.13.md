# WeRelay 0.3.13

发布日期：2026-09-22

## 这次更新

- 手机网页现在能更连贯地显示消息从“发送中”到终端接收、运行和完成的全过程，不会因为桌面端响应稍慢就把已经发出的内容误判为失败或重复显示。
- 新建任务时可以先选择模型和推理强度；只有设置确认成功后才发送第一条消息，已有会话的设置也会继续沿用。
- 网页可以辨认来自其他 Codex 任务的来信，并保留来源和时间，避免把跨任务消息误当成当前用户刚发送的内容。
- DeepSeek Harness 的连接、任务恢复和完成回复更加稳定；较慢的任务列表读取不会再拖住网页、微信和其他终端。

## 修复的问题

- 修复了电脑实际在线时，网页或 ClawBot 偶尔显示离线、任务列表长时间打不开的问题。后台较慢的检查现在会与主连接分开处理，并在失败后保留最近可用列表。
- 修复了微信提问回复可能送到错误任务、恢复期间普通指令无响应，以及非 Codex 终端的完成通知在重启后丢失的问题。
- 修复了审批卡片串到其他任务、完成状态落到旧消息、发送中的消息短暂消失，以及旧的待发送记录长期占住输入区的问题。
- 微信任务列表的正文和操作说明现在分开发送，阅读更清楚；新的短链接不会再因末尾符号被微信截断，已经发出的旧链接仍可使用。
- WorkBuddy 即使尚未建立终端连接也能先查看任务列表；Grok 没有项目归属时也能从“最近”分组新建任务。
- 手机任务默认使用可编辑项目文件的权限；消息正文不再显示内部的桌面传输包装文字。

## 升级说明

- 升级后无需重新配对或迁移任务，重启 WeRelay 即可。
- 如果微信提示发送上下文已失效，请先给 ClawBot 发送一条普通消息刷新会话，再继续操作。
- 等待终端确认超过一小时的旧消息会离开“待发送”列表并回到正文；内容会保留，可以复制、编辑后重新发送或删除本地记录。

## 已知限制

- 电脑睡眠、网络中断或微信长时间未使用后，首次恢复仍可能需要短暂等待；微信上下文失效时必须由一条新的微信消息恢复。
- WorkBuddy 未连接时只能先查看任务列表；进入终端后才会建立连接并开放新建、重命名和发送等操作。
- 本版本继续使用应用层 HTTPS 长轮询连接公网 Relay，不提供独立的通用网络隧道。
