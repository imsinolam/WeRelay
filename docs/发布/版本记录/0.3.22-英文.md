# WeRelay 0.3.22

> Status: locked locally but not published. GitHub checks found dependency advisories and Windows compatibility failures. Fixes continue as 0.3.23 without replacing this artifact.

Release date: 2026-10-30

## Updates

- Versions now use one increasing last number, without separate preview and formal numbering. The computer, taskboard and GitHub share one version so update status is easier to identify.
- More accurately confirm image and queued messages received on the computer, reducing duplicates, entries stuck awaiting confirmation and late results reviving delivered messages.
- Larger task-menu hit areas and added icons; cached task lists stay visible while switching agents, and ordering follows recent real conversations more closely.
- A dedicated Pi Desktop entry continues existing desktop tasks. The case-insensitive WeChat shorthand is `/pi-d`. Pi CLI and Pi Desktop remain separate entries without replacement conversations.
- Choose the next-turn model while Codex is replying; Pi model controls can connect to the original window. The web can also read supported agents’ unsent text drafts without silently overwriting existing drafts.
- ClawBot task lists include web links and simpler guidance. Default lists show more tasks, and failed reads trigger fewer repeated checks.
- Chat text, images, queue cards and the composer share a common implementation, retaining original tasks, drafts and model settings.

## Upgrade

- No new login, pairing or task migration is required. Refresh the web page if an older interface remains visible.
- Existing Pi windows need an idle `/reload` or a normal reopen to load the updated extension; the update does not forcibly close them.
- Pi Desktop requires its authenticated local control interface. If unavailable, WeRelay reports this rather than replacing it with another agent.
- You will verify real Agent and ClawBot messaging, approvals and final replies after deployment. No test messages are sent automatically.

## Known limitations

- Periodic relay disconnections with HTTPS fallback and WSS recovery are still observed. Devices were online during basic checks; this does not certify long-term transport stability.
- Proactive WeChat notifications still require a reply context accepted by WeChat. After a long idle period, sending a fresh message may be necessary.
- Pi Desktop approvals and questions remain desktop-only. Sending the same draft simultaneously from multiple devices is not guaranteed race-free.
- Android shared-web assets and optional signed updates have integration foundations only; this release does not include an Android package or enabled signed asset publication.
