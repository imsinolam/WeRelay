# 任务台消息日历

任务台侧边栏的“消息日历”用于按日期、项目和 Agent 浏览用户消息，支持多词搜索、排序、画布平移缩放与详情查看。首次打开后，在“读取来源”中勾选允许读取的 Agent；默认不读取任何来源。

扫描在运行任务台本地程序的电脑上进行，默认最近 30 个本地日历日。首次扫描异步执行，页面先显示进度，后续访问最多每 60 秒更新索引。当前页面每 5 秒刷新结果，页面不可见时暂停读取。只收录用户消息，不读取助手回复、附件正文或项目源码，不调用模型，不修改 Agent 原始日志。

局域网使用现有本地任务台服务，公网使用现有应用中继和登录会话。服务器不需要安装 Magpie。日历正文不进入 Relay 的预热缓存，也不参与未登录设备的预热；每次读取均由电脑检查登录与来源权限。电脑离线时无法读取新数据。服务本轮最多返回最近 10,000 条、约 12 MiB 消息，单条正文最多 30,000 字；超出时页面提示限制。

读取授权独立于 Magpie，保存到工作区状态目录中的 `message-journal-permissions.json`，权限为 0600。撤销后不再返回该来源正文；其他已打开页面将在下一次可见轮询时清除，不会收回用户此前已经复制或保存的内容。索引仅保存在本地进程内存，不写入插件目录的私人索引，也不读取 Magpie 的分类文件。本阶段不提供模型分类、分类共享或将分类结果自动转成真实 Agent 任务。

## 一处维护，多端复用

`magpie-message-journal` 是解析器、扫描器、日历纯函数、画布和样式的维护源。任务台只实现来源授权、HTTP 接口、主题和导航接入，禁止在 `vendor/message-journal` 中独立修改共享功能。

```bash
# 默认寻找主仓相邻的 magpie-message-journal 目录，Git worktree 也可使用。
npm run journal:sync

# 源码位于其他位置时显式指定；仅对当前命令生效。
MESSAGE_JOURNAL_SOURCE=/path/to/magpie-message-journal npm run journal:sync

# 构建自动同步；没有本地插件目录时校验并使用已提交的快照。
npm run build
```

同步严格限定六个源码/界面文件，不读取或复制 `panel/data.js`、`tasks.json`、配置、凭据和日志。`provenance.json` 记录每个文件的 SHA-256，不记录本机路径。源码修改在下一次同步或构建时带入任务台；应审查同步 diff、运行两边测试，再随本地服务和 Relay 的同一轮正式发布生效。已运行的服务不会因磁盘源码变化自动重新加载。

日历页面与资源使用内容版本，已打开页面每分钟及恢复可见时检查版本。发布时本地和 Relay 必须使用相同包；单独发布其中一端不保证界面与接口兼容。

插件通过可选 `window.JournalHost = { request(path, body), readOnly, refreshMs }` 接口复用画布；未设置时保留 Magpie 原有路径。扫描器支持可选 `allowedAgent(reads, agent)`，任务台借此对 Pi 与 PI-Desktop 分别授权，Magpie 保留原有继承规则。

插件目录当前未纳入 Git。本任务对插件的源码与测试变更保存在 `patches/message-journal/shared-host.patch`，便于恢复或迁移；运行时不应用该补丁。完整维护源仍为用户的插件目录，任务台快照和安装包只包含六个允许分发的文件。

## 验证

```bash
npm run journal:sync
bun test test/message-journal test/daemon/codex-mobile-server.test.ts test/relay
npm run typecheck:src
npm run lint
npm run build
npm pack --dry-run --json

# 在插件目录运行，无运行时 npm 依赖。
npm test
```

HTTP 联调使用独立临时目录、合成 Agent 日志和本机环回端口，验证真实本地服务、Relay 客户端、Relay 服务器与登录权限链路，不读取用户的私人会话。
